# Aether Arcade

Игровой VK-бот на C++20 с Group Long Poll, worker pool и SQLite WAL.

## Архитектура
- C++20, Release-оптимизации и LTO при поддержке компилятора.
- VK Group Long Poll: события поступают через long polling.
- libcurl: HTTP-клиент для VK API.
- Worker pool: выполнение команд вынесено из сетевого цикла.
- SQLite WAL: атомарные ежедневные бонусы и транзакционные переводы.
- CMake, Docker Compose и GitHub Actions.

## Сборка
Требования: CMake 3.24+, компилятор C++20, libcurl и SQLite3. При первой конфигурации CMake загружает nlohmann/json.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
cp config.example.json config.json
# Заполните vk_token и group_id в config.json
./build/vkaether config.json
```

Windows: Visual Studio 2022 с компонентами C++ и CMake. Выполните configure/build через CMake, затем запустите build/Release/vkaether.exe config.json.

В настройках сообщества включите Long Poll API и выдайте токену право отправки сообщений. group_id — положительный числовой ID сообщества без знака минус. config.json исключён из Git; база автоматически создаётся в каталоге data/.

## Команды

Реестр содержит более 130 имён команд, включая русские команды и английские алиасы. Среди них:
- Экономика: `профиль`, `баланс`, `бонус`, `работа`, `топ`, `передать [ID] [сумма]`.
- Игры: `монетка`, `кубик`, `rps`, `число`, `бросок [грани]`, `кости`, `d20`, `дуэль`, `рыбалка`, `охота`.
- Математика: `сумма`, `умножить`, `делить`, `остаток`, `степень`, `факториал`, `простое`, `процент`.
- Развлечения: `загадка`, `викторина`, `предсказание`, `гороскоп`, `анекдот`, `факт`, `квест`, `миссия`.

Часть команд — текстовые мини-игры и генераторы случайных событий. Они не начисляют валюту и не сохраняют инвентарь. Экономические операции используют SQLite.

## Проверки и ограничения

Тесты проверяют регистрацию и ответы новых команд, математические границы, деление на ноль, факториал, проверку простых чисел, ежедневный бонус и транзакционные переводы.

Не заявляем «максимальную» производительность без бенчмарков на целевом сервере. Для дальнейшей production-настройки нужны ограничение очереди задач, rate-limit VK API, упорядочивание команд одного peer_id и метрики latency.
