# Aether Arcade

Игровой VK-бот с полиглотной архитектурой Rust + C++20 + C11 + C# NativeAOT + Go. Сетевой контур работает через VK Group Long Poll, игровые данные — в SQLite WAL.

## Архитектура

| Язык | Зона ответственности | Связь с приложением |
|---|---|---|
| C++20 | VK API, Long Poll, worker pool, команды и игровая логика | Основной native runtime |
| Rust | Вычислительные и доменные примитивы с проверкой переполнения | Статическая библиотека, C ABI |
| C11 | Проверка VK peer/user ID на входе событий | Встроенный native-модуль |
| C# / .NET 8 NativeAOT | Проверка UTF-8, управляющих символов и размера входящих сообщений | Native shared library, C ABI |
| Go | Запуск процесса бота, graceful shutdown, HTTP health endpoints | Production supervisor |

Языки не дублируют одну и ту же работу и не образуют пять сетевых микросервисов. VK-событие проходит проверку C и C# в процессе, затем поступает в C++ dispatcher; Rust вызывается через C ABI для вычислительных операций. Go управляет жизненным циклом native-процесса и предоставляет health endpoints. Это сохраняет короткий путь обработки сообщений без лишних сетевых hops.

Подробная схема и границы модулей: [POLYGLOT.md](POLYGLOT.md).

## Сборка

Основной production target — Linux x86-64.

Требования:
- CMake 3.24+, Ninja, C11/C++20 compiler;
- Rust stable + Cargo;
- Go 1.22+;
- .NET 8 SDK, clang и zlib development headers для NativeAOT;
- libcurl и SQLite3.

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure

cp config.example.json config.json
# Заполните vk_token и group_id в config.json.
go run ./cmd/aetherd -binary ./build/vkaether -config ./config.json -listen :8080
```

При первой конфигурации CMake загружает nlohmann/json. В настройках сообщества включите Group Long Poll API и выдайте токену право отправки сообщений. `group_id` — положительный числовой ID сообщества без знака минус. `config.json` исключён из Git; база автоматически создаётся в каталоге `data/`.

## Использование пяти языков

- Rust: `rsum 12 30` — сложение через Rust C ABI с защитой от переполнения.
- C и C#: проверяют идентификаторы и входящий текст до передачи события игровому dispatcher.
- Go: `/healthz` и `/readyz` возвращают HTTP 200, пока процесс бота работает, и HTTP 503 после его завершения.

## Команды

Реестр содержит более 130 имён команд, включая русские команды и английские алиасы. Среди них:
- Экономика: `профиль`, `баланс`, `бонус`, `работа`, `топ`, `передать [ID] [сумма]`.
- Игры: `монетка`, `кубик`, `rps`, `число`, `бросок [грани]`, `кости`, `d20`, `дуэль`, `рыбалка`, `охота`.
- Математика: `сумма`, `умножить`, `делить`, `остаток`, `степень`, `факториал`, `простое`, `процент`.
- Развлечения: `загадка`, `викторина`, `предсказание`, `гороскоп`, `анекдот`, `факт`, `квест`, `миссия`.

Часть команд — текстовые мини-игры и генераторы событий. Они не начисляют валюту и не сохраняют инвентарь. Экономические операции используют SQLite.

## Проверки и ограничения

GitHub Actions проверяет Rust-модуль, Go supervisor, полную CMake-сборку и C++ tests, включая C/C# ingress validators. Успешность сборки подтверждается только результатом CI; локальный запуск в этой среде не выполнялся.

«Максимальная» производительность не заявляется без бенчмарков на целевом сервере. Следующие отдельные задачи для production: ограниченная очередь задач, rate-limit VK API, упорядочивание команд одного peer_id и метрики latency.
