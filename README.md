# Aether Arcade

Высокопроизводительный игровой VK-бот на C++20 с Group Long Poll, асинхронной обработкой событий и SQLite WAL.

## Архитектура
- C++20, Release-оптимизации и LTO при поддержке компилятора.
- VK Group Long Poll: события поступают через long polling, без частого опроса методов сообщений.
- libcurl: HTTP-клиент с таймаутами и TCP keep-alive.
- Worker pool: выполнение команд вынесено из сетевого цикла.
- SQLite WAL: локальное хранилище, атомарные ежедневные бонусы и транзакционные переводы.
- CMake, Docker Compose и GitHub Actions.

## Сборка
Требования: CMake 3.24+, компилятор C++20, libcurl и SQLite3. При первой конфигурации CMake скачивает nlohmann/json.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
cp config.example.json config.json
# Заполните vk_token и group_id в config.json
./build/vkaether config.json
```

Windows: Visual Studio 2022 с компонентами C++ и CMake. Выполните configure/build через CMake, затем запустите build/Release/vkaether.exe config.json.

В настройках сообщества включите Long Poll API и выдайте токену право отправки сообщений. group_id — положительный числовой ID сообщества без знака минус. config.json исключён из Git; база автоматически создаётся в каталоге data/.

## Игровые команды
Рабочие команды: помощь, профиль, баланс, бонус, работа, топ, монетка, кубик, rps, передать [ID] [сумма], пинг, версия. Реестр содержит более 50 командных имён; игровые подсистемы, которые ещё не реализованы, явно сообщают о подготовке вместо имитации успешной операции.

## Производительность и статус
Текущая версия — начальное ядро. Здесь уже разделены сетевой цикл и обработчики команд, включены WAL и транзакции. Не называем производительность «максимальной» без измерений: для production нужны нагрузочные тесты на целевом сервере, контроль размера очереди, rate-limit VK API, упорядочивание команд в рамках одного peer_id и метрики latency.
